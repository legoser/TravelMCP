# scripts/api-demo.sh — ручное демо и обследование API/MCP

`api-demo.sh` — ручной инструмент для наглядной проверки REST-эндпоинтов и
MCP-инструментов `travelmcp` (curl + jq). Он **не заменяет** автоматические
тесты: регрессионный запуск — это `make test` (unit + integration + smoke).
Скрипт нужен, когда хочется глазами посмотреть поведение API, поиграть с
параметрами или быстро проверить новый сценарий без сборки Go-теста.

Фиксированные сценарии скрипта совпадают с заготовками в `test/common`
(`AssertGroundJourney`, `AssertFlightJourney`, `AssertNoRoute`), поэтому вывод
скрипта можно сверять с ожидаемыми значениями из `AGENTS.md` («Референс
данных»).

## Требования

- Bash, `curl`, `jq` — обязательны.
- Go-тулчейн — только на первый запуск (скрипт сам собирает бинарник
  `bin/mcp-server`, если его нет).
- Свободный порт (по умолчанию `8099`).

## Запуск

```sh
./scripts/api-demo.sh            # порт 8099
PORT=8080 ./scripts/api-demo.sh # свой порт
```

Первый прогон долгий из-за сборки бинарника; повторные — быстрые.

## Что показывает скрипт (по шагам)

1. **healthz / readyz** — живость сервиса и готовность провайдеров.
2. **providers** — `/api/v1/providers`: статус `synth` (up, records).
3. **MCP initialize / tools/list** — рукопожатие Streamable HTTP и список
   инструментов (`find_route`, `list_providers`).
4. **find_route наземка** — Пермь → Екатеринбург, отправление `06:00`:
   цепочка walk → автобус → межгород → walk, прибытие `09:36`, 2 пересадки.
5. **find_route перелёт** — аэропорт → аэропорт, отправление `07:00`:
   перелёт `flight` 08:00–09:05, 0 пересадок.
6. **find_route белое пятно** — кластер C → кластер B: ошибка
   «маршрут не найден» (`isError: true`).
7. **list_providers** — статусы источников через MCP-инструмент.

## Ожидаемые результаты (референс)

| Сценарий | Ожидание |
|---|---|
| Пермь→Екб наземка (06:00) | прибытие `09:36`, 5 legов, 2 пересадки |
| Аэропорт→аэропорт (07:00) | прибытие `09:05`, 0 пересадок |
| Кластер C→B | ошибка «маршрут между c1 и b-mkt не найден» |

## Окружение и временные файлы

- `PORT` — порт сервера (по умолчанию `8099`). Задаётся только через переменную
  окружения, не через аргументы.
- `bin/mcp-server` — собранный бинарник (кэш; отвал ссылается на него).
- `/tmp/travelmcp-demo.log` — лог сервера при сбоях.
- `/tmp/travelmcp-rpc.json`, `/tmp/travelmcp-session.txt` — промежуточные
  ответы MCP и идентификатор сессии.

Сервер останавливается скриптом автоматически (`trap` при выходе).

## Что делать при сбое

- Нет `jq` → скрипт прервётся с сообщением «требуется jq».
- Порт занят → возьмите другой: `PORT=8098 ./scripts/api-demo.sh`.
- Ответ сервера неожиданный → смотрите `/tmp/travelmcp-demo.log` и сравните
  вывод со сценариями `test/common/helpers.go` (`Assert*`).
- Изменили сеть/инструмент в `internal/providers`/`internal/mcp` → удалите
  `bin/mcp-server` (или запустите `make build`), чтобы пересобрать его.

## Связь с тестами

- Автоматические эквиваленты этих сценариев: `make integration`, `make smoke`.
- При добавлении нового поля/инструмента MCP — дополните сценарии в
  `test/common` и, если уместно, этот скрипт (правило из `AGENTS.md`).
