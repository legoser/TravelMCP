# scripts/api-demo.sh — ручное демо и обследование API/MCP

`api-demo.sh` — ручной инструмент для наглядной проверки REST-эндпоинтов и
MCP-инструментов `travelmcp` (curl + jq). Он **не заменяет** автоматические
тесты: регрессионный запуск — это `make test` (unit + integration + smoke).
Скрипт нужен, когда хочется глазами посмотреть поведение API, поиграть с
параметрами или быстро проверить новый сценарий без сборки Go-теста.

Фиксированные сценарии скрипта совпадают с заготовками в `test/common`
(`AssertGroundJourney`, `AssertPlaceJourney`, `AssertFlightJourney`,
`AssertNoRoute`), поэтому вывод скрипта можно сверять с ожидаемыми значениями
из `AGENTS.md` («Референс данных»).

## Требования

- Bash, `curl`, `jq` — обязательны.
- Go-тулчейн — только на первый запуск (скрипт сам собирает бинарник
  `bin/mcp-server`, если его нет).
- Свободный порт (по умолчанию `8099`).
- Необязательный API-ключ: если задан `ADMIN_TOKEN` (в том числе из `.env`),
  скрипт включает авторизацию у сервера и шлёт заголовок `X-API-Key`.

## Запуск

```sh
./scripts/api-demo.sh            # порт 8099, без ключа
PORT=8080 ADMIN_TOKEN=secret ./scripts/api-demo.sh # свой порт + ключ
```

Первый прогон долгий из-за сборки бинарника; повторные — быстрые.
MCP вызывается stateless: **без** `initialize` и без `Mcp-Session-Id` — каждый
запрос обрабатывается как отдельная сессия, ключ передаётся в заголовке.

## Что показывает скрипт (по шагам)

1. **healthz / readyz** — живость сервиса и готовность провайдеров.
2. **providers** — `/api/v1/providers`: статус `synth` (up, records).
3. **MCP tools/list** — список инструментов (`find_route`, `list_providers`)
   первым же запросом, без рукопожатия.
4. **find_route наземка** — Пермь → Екатеринбург по координатам, `06:00`:
   цепочка walk → автобус → межгород → walk, прибытие `09:36`, 2 пересадки.
5. **find_route Юрга → Барнаул** — по населённым пунктам: населённые пункты
   резолвятся в координаты, но маршрута через synth-сеть нет → `isError`.
6. **find_route Пермь → Екатеринбург** — по населённым пунктам: точки
   резолвятся в автовокзалы, межгород без пересадок, прибытие `08:30`.
7. **find_route перелёт** — аэропорт → аэропорт, `07:00`: перелёт `flight`
   08:00–09:05, 0 пересадок.
8. **find_route белое пятно** — кластер C → кластер B: ошибка
   «маршрут не найден» (`isError: true`).
9. **list_providers** — статусы источников через MCP-инструмент.

## Ожидаемые результаты (референс)

| Сценарий | Ожидание |
|---|---|
| Пермь→Екб наземка (06:00) | прибытие `09:36`, 5 legов, 2 пересадки |
| Пермь→Екб по местам (06:00) | прибытие `08:30`, 3 legа, 0 пересадок |
| Аэропорт→аэропорт (07:00) | прибытие `09:05`, 0 пересадок |
| Юрга→Барнаул по местам | ошибка (нет остановок в synth-сети) |
| Кластер C→B | ошибка «маршрут между c1 и b-mkt не найден» |

## Окружение и временные файлы

- `PORT` — порт сервера (по умолчанию `8099`). Задаётся только через переменную
  окружения, не через аргументы.
- `ADMIN_TOKEN` — API-ключ; при задании включает авторизацию (`X-API-Key`).
- `bin/mcp-server` — собранный бинарник (кэш; отвал ссылается на него).
- `/tmp/travelmcp-demo.log` — лог сервера при сбоях.
- `/tmp/travelmcp-rpc.json` — последний ответ MCP.

Сервер останавливается скриптом автоматически (`trap` при выходе).

## Что делать при сбое

- Нет `jq` → скрипт прервётся с сообщением «требуется jq».
- Порт занят → возьмите другой: `PORT=8098 ./scripts/api-demo.sh`.
- Ответ сервера неожиданный → смотрите `/tmp/travelmcp-demo.log` и сравните
  вывод со сценариями `test/common/helpers.go` (`Assert*`).
- Изменили сеть/инструмент в `internal/providers`/`internal/mcp` → удалите
  `bin/mcp-server` (или запустите `make build`), чтобы пересобрать его.

## Связь с тестами

- Автоматические эквиваленты этих сценариев: `make integration`, `make smoke`.
- При добавлении нового поля/инструмента MCP — дополните сценарии в
  `test/common` и, если уместно, этот скрипт (правило из `AGENTS.md`).

# scripts/yandex-collect.sh — точечный сбор фикстур Яндекса (intercity)

Разовый сбор эталонных ответов Яндекс Расписаний для провайдера `intercity`.
Живой API вызывается **только** этим скриптом; Go-адаптер в рантайме Яндекса
не трогает и работает по собранным фикстурам из `testdata/yandex/`.

## Требования

- Bash, `curl`, `jq`.
- Ключи в окружении (не в репозитории!):
  `YANDEX_RASP_KEY`, `YANDEX_GEOCODE_KEY`.

## Запуск

```sh
export YANDEX_RASP_KEY=... YANDEX_GEOCODE_KEY=...
./scripts/yandex-collect.sh
YANDEX_DATE=2026-09-05 ./scripts/yandex-collect.sh  # фиксированная дата
```

## Что делает

1. Геокодит 4 города (`nsk`, `barnaul`, `tomsk`, `kemerovo`) → координаты.
2. `/nearest_stations` → код станции (автовокзал).
3. `/schedule` для каждой станции (рейсы + `timezone` станции).
4. `/search` для пар НСК↔Барнаул, НСК↔Томск, НСК↔Кемерово (`transport_types=bus`).
5. Режет большие ответы, копирует в `testdata/yandex/`.

Сырьё: `data/yandex/raw/` (не коммитится); фикстуры: `testdata/yandex/`
(коммитятся вместе с кодом адаптера).

## Почему не в Go-тестах

Тесты по замыслу офлайн: адаптер Яндекса гоняется на фикстурах (тест-дабл),
реальные запросы к API запрещены (правило из `docs/07-first-provider-plan.md`).

## Подводные камни API (обнаружено при сборе)

- Базовый URL `api.rasp.yandex.net/v3.0`: пути без завершающего слеша отдают
  `302` → нужен `curl -L`, иначе ответы пустые.
- `date` — строго `YYYY-MM-DD`; литерал `today` не принимается.
- `system=standard` не существует (`v3.0_36`); коды `s…` — уже код Яндекса.
- `station_type` бывает `bus_station`/`station`/`stop`/`bus_stop`/`airport`.
- Геокодер: `geocode-maps.yandex.ru/1.x/` + `apikey`; координаты в `Point.pos`
  формата «lng lat» (инвертированы относительно ответа).
- Автовокзал Томска на дату сбора отдал 0 отправлений — фильтровать станции
  по `station_type==bus_station` и иметь fallback на `/search` по паре.

Детали — в `docs/07-first-provider-plan.md`, этап 0.2.

# scripts/extract-minstran.py — реестр Минтранса → JSON датасет

Извлекает из XLSX-реестра межрегиональных маршрутов Минтранса маршруты,
остановки и расписание по заданным регионам. Выход: `data/reestr/regions.json`
(не коммитится; сырьё для standalone-коннектора `tools/registry-parser`).

```sh
# сырьё: data/raw/minstran/reestr.xlsx (ручная/curl-загрузка с mintrans.gov.ru)
python3 scripts/extract-minstran.py --in data/raw/minstran/reestr.xlsx \
  --out data/reestr/regions.json
```

Параметры фильтрации регионов — в начале скрипта (`REGIONS`).

# tools/registry-parser — срез реестра → flat_trips.json

Standalone-коннектор (отдельный Go-модуль, без зависимостей от `internal/`):
единственное место, знающее специфику формата Минтранса. Переводит срез
реестра в универсальный flat-формат для `cmd/trips-sync`.

```sh
cd tools/registry-parser
go run . --input ../../data/reestr/regions.json \
  --out ../../data/reestr/flat_trips.json \
  --source gov-registry --trust-nk
# bootstrap NK-стабильности (сравнение двух срезов, churn-порог):
go run . --input new.json --bootstrap old.json --churn 0.2 --out flat_trips.json
```

`--trust-nk` — использовать reg-код как ключ маршрута (после
bootstrap-подтверждения стабильности); по умолчанию синтезированный ключ.

Схема XLSX задокументирована в `docs/07-first-provider-plan.md` (этап 0.1).

# scripts/make-places.py — газетир населённых пунктов

Генерирует `internal/geo/places.json` — локальный справочник «населённый пункт
→ координаты» для `find_route` по названию (`from_place`/`to_place`). Пока это
замена внешнего геокодинга: только автовокзалы/автостанции/аэропорты из
`data/osm/stations.json` + редкие курируемые точки.

```sh
python3 scripts/make-places.py   # требует data/osm/stations.json (не коммитится)
```

Правила генерации: в топоним берётся первое слово названия без слов-признаков
(автовокзал/автостанция/аэропорт/межгород), срезаются суффиксы `-Главный/-2/…`
и статьи (`г.`, `с.`); приоритет — именованные автовокзалы > автостанции >
тег `amenity=bus_station` > аэропорты. Выход коммитится; рантайм читает его
через `go:embed`.

Помимо словаря, при старте в газетир добавляются остановки провайдеров
(по первому слову названия до запятой — «Пермь» из «Пермь, Центральная
площадь»), поэтому «Пермь»/«Екатеринбург»/«ПГУ» резолвятся и без OSM-данных.
