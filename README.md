# travelmcp

MCP-сервер для поиска мультимодальных маршрутов общественным транспортом «дверь-в-дверь»: из ближайшего к указанному местоположению пункта отправления в ближайший пункт назначения.

## Цель проекта

Спроектировать и реализовать систему, которая по запросу пользователя (в том числе от ИИ-агента через MCP) строит цепочку перемещений между двумя точками с учётом общественного транспорта, стыковок и «белых пятен» покрытия.

Ключевые свойства:

- **Мультимодальность.** Цепочка может состоять из одной поездки или из нескольких поездок разными видами транспорта с разными стыковками по времени.
- **Ближайшие точки.** Отправление и назначение ищутся как ближайшие доступные пункты посадки/высадки к указанному пользователем местоположению.
- **Честные «белые пятна».** Если населённый пункт или участок не имеет цифровизованного сообщения общественного транспорта, маршрут не «обрывается», а помечает такой сегмент как самостоятельный (пешком / такси / авто) — ответственность за него несёт пользователь. Итог всегда «дверь-в-дверь».
- **Модульные источники данных.** Провайдеры данных разнообразны. Источники подключаются как модули-адаптеры, приводящие данные к единой канонической модели. Это обеспечивает гибкость развития: добавить источник — значит написать один адаптер.
- **Динамическая конфигурация** с самого начала: конфигурация проекта и настройки поиска маршрутов изменяются без пересборки, per-user.
- **Персональные настройки поиска.** Параметры поиска (виды транспорта, лимит пересадок, радиус пешей доступности и т.п.) уникальны для каждого пользователя; идентификация — по API-ключу.
- **Интерфейс управления.** Регистрация и модерация пользователей, управление подключёнными источниками данных, дашборд здоровья сервиса, внешних запросов и нагрузки.
- **Готовность к стоимости.** Заложен интерфейс учёта стоимости для разных конфигураций передвижения (реализуется на последующих этапах).

## Технологии

- **Язык**: Go (модуль `travelmcp`).
- **MCP**: официальный `modelcontextprotocol/go-sdk` + `mark3labs/mcp-go`; транспорт — удалённый Streamable HTTP (спецификация MCP 2026-07-28, stateless).
- **Хранилище**: PostgreSQL + PostGIS (пользователи, api-ключи, конфиг, кэш фидов, счётчики метрик).
- **Данные**: только открытые бесплатные источники (реестры Минтранса РФ, GTFS Москвы/СПб, OpenStreetMap); платные API на первом этапе не используются.
- **Observability**: OpenTelemetry, Prometheus/Grafana; health-эндпоинты; метрики по каждому внешнему источнику.

## Рабочие данные (не коммитятся)

`data/` — сырьё и датасеты сбора провайдера `intercity`: реестр Минтранса
(`data/raw/minstran/`), выгрузка по 4 регионам (`data/reestr/regions.json`),
OSM-гео-метки (`data/osm/stations.json`), сырые ответы Яндекса
(`data/yandex/raw/`). Эталонные фикстуры для тестов — в `testdata/`
(коммитятся).

## Статус

Go-каркас реализован: MCP-сервер (Streamable HTTP stateless, без рукопожатий
и сессий; API-ключ через заголовок `Authorization: Bearer` / `X-API-Key` при
заданном `ADMIN_TOKEN`), инструменты `find_route` (по координатам либо по
населённому пункту через локальный газетир) и `list_providers`; HTTP-эндпоинты
(`/healthz`, `/readyz`, `/api/v1/providers`, `/api/v1/dashboard` с той же
авторизацией), ядро CSA-планировщика и телеметрия. Продакшн-источников по
умолчанию нет (подключаются по мере реализации, см. `docs/05-roadmap.md`);
синтетическая сеть `synth` — мок только для тестов/демо (`PROVIDERS_ENABLED=synth`).
Тестирование — через `make test` (unit + integration + smoke).
